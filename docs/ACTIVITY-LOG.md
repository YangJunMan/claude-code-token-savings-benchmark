# 활동 단위 토큰 측정

결과표는 "얼마나 줄었나"만 답한다. 이 문서는 **어디서** 줄었는지 보는 방법을 설명한다.

## 왜 필요한가

`data/published-measurements.csv`는 실행 하나당 한 줄, 합계만 담는다. 독자는
"Headroom이 36.7% 줄인다"는 결론을 볼 수 있지만 그 절감이 어느 활동에서 생겼는지는
확인할 방법이 없다. 근거의 해상도를 한 단계 낮추는 것이 이 측정의 목적이다.

## context tax

tool result가 컨텍스트를 키우면 그 비용은 한 번이 아니다. 남은 모든 턴이 그것을 다시
읽으므로 **턴 수만큼 반복 청구**된다.

```
턴 컨텍스트 = input + cache_creation + cache_read   (provider 보고값)
result      = 컨텍스트 증가분 − 직전 턴 output
context tax = result × 이후 남은 턴 수
```

`result`는 provider가 보고한 값들의 뺄셈이지 추정이 아니다. 두 턴 사이에 컨텍스트를
키울 수 있는 것은 모델이 쓴 출력과 도구가 돌려준 결과뿐이므로, 전자를 빼면 후자가 남는다.

실측 예 — 파일럿 실행에서 `Read` 15개를 한 턴에 병렬 호출했다.

```
입력   4,861 토큰
청구 121,525 토큰   (25.0배)
```

Headroom과 RTK가 공격하는 지점이 정확히 여기다.

## 결과는 호출한 턴에 귀속시킨다

턴 N이 호출한 도구의 결과는 턴 N+1의 컨텍스트에서 처음 관측된다. 그 크기를 턴 N+1에
기록하면 **그 턴이 호출한 다른 도구에 잘못 붙는다.** 그래서 관측된 값을 호출한 턴으로
되돌려 기록한다. 마지막 턴은 뒤따르는 턴이 없으므로 결과 크기를 알 수 없고 0으로 둔다.

## 회계가 맞는지 검증한다

재청구된 컨텍스트를 네 원인으로 분해한다.

| 항목 | 뜻 |
|---|---|
| 초기 컨텍스트 | system prompt, 도구 정의, 과제. 이후 모든 턴이 다시 읽는다 |
| 모델 출력 | 각 턴의 출력이 대화에 누적되어 이후 턴에 실린다 |
| tool result | 도구가 돌려준 내용 |
| 버려진 컨텍스트 | 컨텍스트가 줄어든 만큼 (음수) |

네 항목의 합은 provider가 실제로 다시 읽은 양과 **정확히 일치**한다. 일치하지 않는
실행은 발행하지 않는다. 페이지가 "분해가 실측과 같다"고 주장하는 근거가 이것이다.

## 측정 불가 판정

컨텍스트가 중간에 줄어든 실행(compaction)은 회계는 균형을 유지하지만 **측정 불가**로
표시한다. 버려진 결과는 이후 턴이 다시 읽지 않으므로 context tax가 과대계상되는데,
무엇이 버려졌는지는 transcript에서 복구할 수 없기 때문이다.

`run-summary.csv`의 `measurable` 열이 이 판정을 담는다.

## 브라우저에서 보기

```bash
python3 -m http.server 8765
# http://127.0.0.1:8765/web/
```

> `index.html`을 더블클릭해 `file://`로 열면 브라우저가 CSV 읽기를 막는다.

| 화면 | 보여주는 것 |
|---|---|
| 턴별 context tax | 각 턴의 도구 호출이 이후 턴들에 걸쳐 청구시킨 총량 |
| 컨텍스트 성장 | 턴이 진행되며 매 턴 다시 실리는 컨텍스트 크기 |
| 재청구된 컨텍스트의 출처 | 위 네 항목으로 분해한 스택 막대 |
| 툴별 누적 tax | 어떤 도구가 컨텍스트를 가장 많이 불렸는지 |
| 진행 과정 재생 | 턴을 하나씩 드러내며 컨텍스트가 부푸는 과정 |

의존성이 없고 빌드 단계도 없다. 페이지는 아무것도 다시 계산하지 않는다 — 모든 수치를
아래 CSV에서 읽는다.

## 데이터 스키마

### `data/activity-log.csv` — 턴당 한 줄

| 열 | 뜻 |
|---|---|
| `run_date` | 회차. 주 1회 실험이 쌓이면 행만 늘어난다 |
| `run_id`, `condition` | 실행 식별자와 조건 |
| `turn` | 턴 번호 (1부터) |
| `tools` | 그 턴이 호출한 도구들 (공백 구분) |
| `input_tokens`, `cache_creation_tokens`, `cache_read_tokens`, `output_tokens` | provider 보고값 |
| `context_tokens` | 앞 세 입력 항목의 합 |
| `result_tokens` | 이 턴이 호출한 도구들의 결과 크기 |
| `discarded_tokens` | 설명되지 않는 감소분 (compaction) |
| `context_tax_tokens` | `result_tokens × 이후 남은 턴 수` |
| `compacted` | 이 턴에서 컨텍스트가 줄었는지 |

### `data/run-summary.csv` — 실행당 한 줄

`cost_usd`, `quality_score`, `critical_pass`, `turns`, `measurable`, 그리고 위 분해
결과(`reconcile_*`). **토큰 합계 열은 없다** — activity-log에서 전부 파생되므로 두 곳에
적으면 서로 어긋날 수 있다.

## 원본 아티팩트

`benchmark/runs/<회차>/<실행>/attempt-NN/`에 transcript, diff, 채점 결과가 남는다.
용량이 크고 개인정보와 로컬 경로가 포함될 수 있어 저장소에는 커밋하지 않는다.
공개되는 것은 위 두 CSV뿐이며, 그것으로 페이지의 모든 수치를 역추적할 수 있다.
