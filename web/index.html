어떤 절약법도 확실한 효과가 확인되지 않았습니다

실행 하나하나의 비용

점 하나가 실행 1회입니다. 회색 띠는 아무 설정도 하지 않은 BASE가 흔들린 범위입니다. 다른 기법의 점이 이 띠 안에서 BASE와 겹치면, 차이를 효과로 볼 수 없습니다.

비교한 기법

Claude Code의 비용과 토큰을 아껴 준다고 알려진 4가지 방법을 아무 조치도 하지 않은 BASE와 같은 조건에서 비교했습니다.

BASE아무 절약 설정도 추가하지 않은 기본 Claude Code 실행입니다. 모든 비교의 기준이 됩니다.
BE_BRIEF시스템 프롬프트에 간결하게 답하라는 짧은 지시문 두 줄을 덧붙입니다.
CAVEMAN-FULL불필요한 설명을 빼고 아주 짧은 문장으로만 답하도록 프롬프트와 플러그인으로 강하게 지시합니다.
HEADROOM로컬 프록시 서버를 거쳐 이전 대화에서 반복되는 내용을 캐싱하고 압축합니다.
RTK셸 훅을 이용해 터미널 명령어의 긴 출력을 모델에 전달하기 전에 요약합니다.

BASE 대비 증감률

왼쪽이 절감, 오른쪽이 증가입니다. 막대 뒤 회색 띠 안의 차이는 같은 설정끼리도 생기는 흔들림 수준입니다.

읽는 법과 용어
  1. 왼쪽 그래프에서 기법마다 점(실행 1회)이 어디에 모여 있는지 봅니다.
  2. 회색 띠는 BASE끼리도 이만큼 달라진다는 범위입니다. 다른 기법의 점들이 띠 안에 있으면 차이가 우연일 수 있습니다.
  3. 띠를 확실히 벗어난 기법이 있어야 "효과가 있다"고 말할 수 있는데, 이번 실험에는 없었습니다.
흔들림 폭 (noise floor)
같은 설정(BASE)으로 여러 번 돌려도 결과가 이만큼 달라집니다. 이 안의 차이는 우연일 수 있습니다.
토큰
모델이 읽고 쓴 글자 단위의 양입니다. 많을수록 비용이 늘어납니다.
회차
같은 날 묶어서 돌린 한 번의 측정입니다.

선택한 실행의 결과

어느 대화 단계(턴)에서 토큰이 많이 불어났을까요?

한 턴에서 읽은 파일이나 명령어 출력은 대화가 끝날 때까지 매 턴 다시 읽히며 비용이 거듭 청구됩니다. 이렇게 누적된 양을 반복 청구 토큰(context tax)이라고 부릅니다. 막대가 높을수록 그 턴에서 들어온 내용이 전체 토큰 소모를 크게 늘렸다는 뜻입니다.
